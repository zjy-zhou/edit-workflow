## 1. 核心判断

本项目应作为 Dify 之上的电商业务层实现，而不是重写 Dify 的工作流引擎。

Dify 继续负责：

- 应用创建与管理。
- 工作流草稿图编辑。
- 自然语言生成工作流。
- 工作流运行与运行日志。
- 模型、工具、权限、工作空间等基础设施。

新增电商业务层负责：

- 面向任务的 SOP 执行体验。
- 搜索主图策划、商机发现等电商任务类型。
- 面向电商场景的自然语言生成入口。
- 围绕商品、竞品、报告、产物的业务上下文。
- 与两个 YY Demo 对齐的简化业务界面。

## 2. 成功标准

首个可交付版本满足以下目标即视为成功：

1. 用户进入平台后看到电商业务导向的导航、品牌和页面结构。
2. 用户可以在应用中心浏览电商应用或场景应用。
3. 用户可以通过一句话描述或上传材料创建电商场景。
4. 用户可以将生成的场景发布为 Dify 工作流应用。
5. 用户可以从任务类型创建任务，例如“搜索主图策划”或“商机发现”。
6. 用户可以按预设 SOP 执行任务并查看当前步骤状态。
7. 用户可以查看中间产物和最终报告。
8. 用户可以回看历史任务，并追溯到底层 Dify 工作流运行记录。

技术成功标准：

- 现有 Dify 应用、工作流、运行日志页面不被破坏。
- 场景生成复用 Dify 已有工作流生成和草稿同步能力。
- 任务记录独立持久化，同时关联 Dify app、workflow、workflow_run。
- 权限检查继续基于工作空间和现有 Dify 权限体系。
- 新增能力可回滚，不污染或破坏 Dify 原有核心数据。

## 3. 用户与使用场景

### 电商运营人员

目标：无需理解完整工作流编辑器，也能执行标准化电商增长任务。

典型任务：

- 从任务类型启动标准任务。
- 导入或选择商品信息。
- 确认 AI 推荐的竞品、策略或执行选项。
- 获得主图策划、视觉策略、商机报告或生成产物。

### 工作流搭建人员

目标：通过自然语言、文档或画布快速创建可复用的电商场景应用。

典型任务：

- 描述想搭建的电商场景。
- 让系统生成工作流。
- 检查并调整工作流画布。
- 发布为可复用应用。

### 工作空间管理员

目标：保证权限、安全、可追溯和可管理。

典型任务：

- 控制谁可以创建应用和任务。
- 审计任务执行与工作流运行。
- 管理生成应用的可见性。
- 避免跨工作空间的数据泄漏。

## 4. 产品范围

### MVP 范围内

- 电商平台导航与品牌壳。
- 应用中心视觉和交互改造。
- 场景中心：一句话生成电商场景。
- 任务中心：任务列表、筛选、创建、详情。
- 初始任务类型。
- 任务 SOP 步骤展示与执行状态。
- 商品选择或导入流程。
- 任务产物和报告展示。
- 任务与 Dify 应用、工作流运行记录的关联。
- 基础任务状态持久化。

### MVP 暂不包含

- 完整替代 Dify Marketplace。
- 重写 Dify 工作流画布。
- 重写 Dify 应用执行引擎。
- 未经审批的电商平台爬取能力。
- 计费体系改造。
- 独立于 Dify 的复杂角色权限体系。
- 完整图片生成生产链路，除非已有可用模型或工具提供方。

推荐导航结构：

| 导航项 | 路由 | MVP 行为 |

| 我的任务 | `/tasks` | 任务列表与任务详情入口 |

| 场景中心 | `/scene-center` | 自然语言生成电商场景 |

## 6. 功能需求

### 6.1 导航与品牌

需求：

- 将 Dify 默认导航替换为电商业务导航。
- 保留工作空间、账号、帮助等基础入口。
- 创建类操作继续受 Dify 权限控制。
- 现有 Dify 路由仍可访问，避免阻断原系统能力。

验收标准：

- 用户可从主导航进入我的任务、应用中心、场景中心。
- `/apps` 和 `/app/{appId}/workflow` 仍可正常访问。
- 无创建权限的用户看不到创建应用、创建任务、创建场景等操作。

### 6.2 应用中心

应用中心是面向电商运营视角的 Dify 应用列表。

需求：

- 应用卡片视觉对齐设计稿。
- 支持“全部”“我创建的”“我收藏的”等页签。
- 支持搜索。
- 支持分类标签，例如市场洞察、商品运营、内容创作、付费推广、新品开发。
- 支持“获取 / 已获取”语义，用于推荐应用或模板应用。
- 保留 Dify 应用打开、编辑、复制、删除等能力，并按权限展示。

验收标准：

- 已存在的 Dify 应用能以电商应用卡片展示。
- 搜索和筛选可以影响列表结果。
- 点击工作流应用仍进入 Dify 工作流编辑器。
- 样式改造不丢失原应用元数据。

### 6.3 场景中心

场景中心用于通过提示词、附件、文档或画布方式创建电商工作流应用。

需求：

- 提供输入框：“告诉我你想创建的场景内容，一键生成电商场景...”
- 提供快捷标签：市场洞察、商品运营、内容创作、付费推广、新品开发。
- 在已有文件能力允许的前提下支持图片和文档上传。
- 调用 Dify 已有工作流生成流式接口生成工作流图。
- 展示生成进度，包括计划阶段和结果阶段。
- 用户可将生成结果发布为 Dify 工作流应用。
- 发布后跳转到对应工作流编辑器。

验收标准：

- 用户输入提示词后可以生成工作流图。
- 生成结果可以应用到新的 Dify 应用。
- 生成失败时保留用户输入，并展示可恢复错误。
- 空提示词或超长提示词在发起生成前被拦截。

### 6.4 任务中心

任务中心是电商业务执行层。

需求：

- 展示任务列表。
- 支持全部、未完成、已完成等页签。
- 支持按任务名称或描述搜索。
- 支持按任务类型筛选。
- 任务卡片展示标题、描述、类型、状态、关联商品、创建时间或更新时间。
- 提供创建任务弹窗。
- 创建任务需要填写任务名称、任务描述、任务类型。

初始任务类型：

- 搜索主图策划
- 商机发现

验收标准：

- 用户可以从任务类型创建任务。
- 任务创建后刷新页面仍存在。
- 筛选结果与任务真实状态一致。
- 点击任务卡片进入任务详情。

### 6.5 任务详情与 SOP 执行

任务详情将 Dify 工作流运行包装成电商 SOP 执行体验。

需求：

- 展示任务标题、描述、状态、关联商品。
- 展示 SOP 步骤列表。
- 展示当前步骤和已完成步骤。
- 支持步骤级输入和确认。
- 底层工作流运行时展示实时或准实时执行状态。
- 展示中间产物。
- 展示最终报告或输出。
- 提供底层 Dify 工作流运行日志入口，方便审计和排查。

初始 SOP：

商机发现：

1. 精准词获取
2. 社媒人群画像获取
3. 竞品获取
4. 评价问大家数据获取
5. 商机发现报告生成

搜索主图策划：

1. 主图策划案生成
2. 主图视觉策略生成
3. 主图生成

验收标准：

- 未解锁步骤不能被随意跳过，除非产品明确允许。
- 步骤完成后任务状态会更新。
- 工作流执行失败后，任务状态进入失败并提供重试入口。
- Dify 工作流运行日志仍可追溯。

### 6.6 商品与竞品上下文

需求：

- 为任务保存选中或导入的商品信息。
- 商品信息包含商品名称、描述、图片、文件、平台、类目等字段。
- 保存 AI 推荐或用户选择的竞品。
- 商品和竞品数据必须限定在工作空间与任务范围内。

验收标准：

- 任务详情刷新后仍能展示商品信息。
- 竞品确认结果可以被后续 SOP 步骤使用。

### 6.7 产物与报告

需求：

- 保存任务步骤生成的产物。
- 产物类型包括报告、策略卡、图片、表格、文件、文本块、外部链接。
- 产物关联任务、步骤，并尽量关联底层 workflow_run 或 node_execution。
- 用户可以从任务历史中查看产物。

验收标准：

- 任务完成后的最终报告可再次打开。
- 步骤输出可以追溯到产生它的步骤或运行记录。

## 7. 非功能需求

### 安全

- 所有电商任务 API 必须做 tenant 隔离。
- 复用 Dify 登录态和工作空间权限上下文。
- 不允许跨工作空间读取工作流运行数据。
- 文件上传继续走 Dify 现有大小、类型、安全校验。
- 不新增匿名任务或匿名文件接口。

### 性能

- 任务列表必须支持分页或无限加载。
- 应用中心保留现有分页能力。
- 长耗时生成和执行使用流式接口或轮询，不阻塞页面加载。
- 任务详情首屏不加载完整运行日志。

### 兼容性

- 现有 Dify 应用、工作流、知识库、工具、市场页面继续可用。
- 新增数据库表为增量表，不修改核心表语义。
- 回滚时不要求删除 Dify 核心记录。

### 可观测性

- 记录任务状态流转。
- 保存 workflow_run_id 以便追踪。
- 生成失败时尽量保存稳定错误码。

## 8. 压力测试

### 主要失败模式

| 失败模式 | 影响 | 应对要求 |
| --- | --- | --- |
| 工作流生成失败 | 用户无法创建场景 | 展示可恢复错误，保留提示词和附件 |
| 应用创建成功但图同步失败 | 出现孤儿应用 | 复用已有回滚逻辑，失败时暴露孤儿 app_id |
| 任务步骤执行失败 | 任务卡住 | 标记步骤失败并允许重试 |
| 用户会话中权限变化 | 非法更新 | 服务端每次更新重新校验权限 |
| 商品文件过大或类型不支持 | 任务配置失败 | 走 Dify 文件校验并展示原因 |
| 设计稿中存在假数据 | 实现误导 | 生产环境必须读 API，mock 仅限开发演示 |
| `/apps` 原能力回归 | Dify 用户受阻 | 保留原 API 与路由契约 |

### 阻塞项

- 需要产品确认：MVP 的任务执行是否必须真实调用 Dify 工作流，还是可先用 mock 步骤产物。
- 需要明确任务类型 schema 和商品必填字段。
- 需要确认电商数据采集、图片生成、竞品分析相关模型或工具是否可用。

### 可控风险

- UI 与设计稿细节偏差：可通过 Playwright 截图和组件验收控制。
- 工作流生成质量不稳定：可通过电商模板提示词和示例约束。
- 迁移复杂度：新增表为主，可控。

## 9. MVP 切分

P0：

- 导航与品牌。
- 应用中心改造。
- 场景中心提示词生成工作流。
- 任务列表、创建、详情与持久化状态。
- 任务关联 Dify app 和 workflow_run。

P1：

- 商品导入。
- 竞品确认。
- 步骤级产物。
- 报告展示优化。
- 任务类型管理。

P2：

- 真实电商数据连接器。
- 图片生成链路。
- 经营增长看板。
- 能力中心。

## 10. 开放问题

1. “应用中心”只展示 Dify 应用，还是同时展示电商推荐模板？
2. “获取”表示复制模板、安装推荐应用，还是收藏？
3. 精准词、人群画像、竞品、评价问大家数据来自哪些合规数据源？
4. 任务产物默认仅创建人可见，还是工作空间可见？
5. MVP 是否需要导出 PDF 或 Word 报告？
6. 任务类型定义是代码内置、管理员配置，还是从 Dify 工作流模板导入？
